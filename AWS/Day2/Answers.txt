Bastion Host:
    It is like a jump box, where we can ssh to the priavte subnet vm by ssh to this bastion host.
    To achieve this, we need to allow sg of this vm in the inbound rule of priavte vm

NAT instance:
    It is older way to give priavte vm the access to connect to internet.
    It is also a instance with diabled option of inbound/outbound traffic check
    then in private vm route add this vm through which you access the internet

NAT gateway:
    It is the modern way to give the private vm to internet connection.
    It is a aws component, we create that connect the route in such way other routes except local are going through nat gateway
    It is more easier

When to use:

Bastion Host - When you need to connect to that vm more securely
Nat instance - Older way or used in legacy systems, usally when to need to NAT RULES and packet filtering etc.
Nat Gateway  - When we give the priavate vm the access to internet to update any package or setup anything
